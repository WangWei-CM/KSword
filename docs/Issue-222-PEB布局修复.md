# Issue 222：PEB 布局与详情投影修复

## 问题与根因

[原 issue 与截图](https://github.com/KSwordDEV/KSword/issues/222) 显示进程详情 PEB 页的操作行上下出现大片空白，参数卡片被挤到底部，摘要不可见，只读说明默认折叠，输入行高和卡片圆角不一致。

2026-10-13 使用仓库已有 Release 主程序，以普通权限打开自身进程详情并首次切到 PEB，在真实窗口复现了上述布局。可访问树中没有摘要 `RegionCount` 和说明 `VirtualAddressRegionPreview`，仅存在说明折叠按钮。

- `DetailWindowFramework::replaceDetailWidget` 原来将 `isHidden()` 当成业务显式隐藏；惰性构造的新子控件也可能暂时隐藏，替换后的投影因此被永久隐藏，剩余操作行被布局拉高。
- PEB 仍使用纵向参数滚动区加结果视图，参数区被限制为 280px，未使用参数操作页共享骨架。
- 受 `DetailLayoutRegistry` 管理的字段源被替换投影并重挂父对象，会破坏详情宿主缓存的直接面板身份；线程页属于真实同类入口。

## 导航、分类与共享入口

路径均相对 `Ksword5.1/Ksword5.1/`。

| 导航或受影响类型 | 页面类型 | 共享入口与处理 |
| --- | --- | --- |
| 进程 → 进程详细信息 → PEB（惰性页） | 参数执行 + 字段详情 | `ParameterWorkspace`、`StyleParameterSection`、`ConfigureDetailForm`、显式 `CreateDetailFieldProjection` |
| 进程 → 进程详细信息 → 线程 → 当前行详情 | 列表 + 受管字段详情 | 原 `DetailLayoutRegistry` 继续管理原字段对象；框架只替换其内部展示 |
| 独立详情窗口中的惰性 Tab/字段投影 | 属性与字段详情 | `InstallDetailWindowFramework` 仅继承 `WA_WState_ExplicitShowHide` 所证明的业务隐藏 |
| 详情窗口中的 `ParameterWorkspace` | 参数执行 | 骨架自身声明布局边界，通用详情兼容层不进入分栏、表单和滚动区 |
| 进程详情 → 内存 → 进程/内核内存证据、PTE 转换 | 参数执行 + 原生字段树 | 参数边界内未显式投影的字段保持原生树同步首显，不延迟为待淘汰视图 |

对照系统变速、虚拟定位的参数骨架，并检查进程详情操作页、令牌开关页及其共享实现。其它操作页已有自然排列和尾部 stretch，没有证据支持扩大重排。

## 修复后的结构与源码核对

- PEB 参数正文自然排列并独立滚动；执行按钮固定于参数栏底部，状态与摘要保留在结果栏。宽窗并列，窄窗由共享分隔器切为上下排列，长标签由 `QFormLayout::WrapLongRows` 换行。
- 只读说明默认显示于参数正文，不再折叠，也不创建第二个说明滚动区。摘要独立滚动；两者继续使用同一份 `FieldDocument` 和原搜索、复制、导出动作。
- 页根只有一层 6px 留白；卡片、输入尺寸和圆角由共享组件提供，不为结果区另画外圆。PEB 没有结果表格，不适用表格操作条、列组或快照对比。
- 应用动作声明强调色，提示去掉错误方位词，zh-CN/en-US 定点同步。保留输入对象、Native/Wow64 目标、权限检查、异步刷新与原写入信号。
- 字段投影根据参数表面祖先使用参数正文底色，独立详情保留原页根底色；视口显式同底。新建子控件临时隐藏不再继承到替换宿主；已有业务显式隐藏仍保留。
- 受管字段内嵌投影继续保留原对象和分隔器直接子身份，旧字段树由 `setDocumentOnly()` 销毁。没有新增源码，无需工程登记。
- 参数布局边界使用独立 `ksword_parameter_workspace` 标记，不复用专业控件的 `ksword_detail_keep_layout`。标准主题继续接入普通参数控件；原生字段树的首显判断也识别该边界。投影底色查找到本窗口即停止，缓存记录实际底色与文字色。
