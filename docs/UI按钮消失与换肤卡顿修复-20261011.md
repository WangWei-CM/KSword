# 按钮底色消失、主题卡顿与 WinAPI 图标修复

## 已确认的源码链

1. Dock 内容构造完毕后，宿主追加 `QWidget{background:transparent}`，作用于整页后代。原本通过继承样式显示的按钮/卡片也被重新设为透明，并触发整页样式重算。现在只声明 Dock 根节点的透明表面，完整拥有块可由共享按钮组件精确排除。
2. `ThemedButtonStyle()` 首先按 QPushButton 生成实底，但使用 Auto 标记。首次排队绑定拿到真实控件后，旧判断把“无文字、有图标”的 QPushButton 当成 Flat。内核命名空间、Atom、NtQuery 等刷新动作会从实底变成透明。现在普通动作工厂明确 Solid，Auto 对 QPushButton 只尊重 `isFlat()`，不按文字猜用途；页面明确外观不能被旧 Auto 标记撤销。
3. SVG 管理器每次 StyleChange 又为同一按钮创建引擎并 setIcon。图标引擎每次 paint 重新搜索对比度并 SourceIn 着色。现在按按钮原图/强调色复用包装，按实际配方输入缓存状态颜色，按真实前景、源位图、设备请求和原生禁用输入复用 Qt 有限位图缓存。
4. 权限状态定时器每轮重写相同 QSS；标题栏多个无变化状态 setter 反复重登记按钮、换图标、同步调用 EXE Shell 图标查询。现在相同样式/状态不重写，标题资源复用现成 QIcon 或已映射原生资源，真实状态与主题变更仍更新。
5. 主题刷新曾重建整个进程表和隐藏线程表。主表颜色已有动态数据角色，改为绘制刷新；线程委托按每格原有风险/退出画刷标记读取当前主题，保留重复 PID/TID 行的独立语义，不扫描全快照。窗口审计表不再为普通文本与交替行逐单元格固化中性色。
6. 旧颜色补偿仍在同步路径遍历全应用并写入 QSS/palette，不受主题绑定预算限制。主入口改为分片队列；连续 A→B→C 保留尚未转换的基线链，业务新覆盖、显式画刷变更、销毁对象和过期回调均有独立保护。

## 图标范围和远端合并

- WinAPI 监控替换 8 个旧 Qt 系统图标入口：刷新进程、浏览 DLL、启动、停止、终止 Hook、导出、清空事件、清空筛选。
- 4 个规则动作补相同语义 SVG，保留原文字、释义和业务连接。停止使用现成方形 Stop 资源的新 alias；按钮仍采用 Neutral/Accent/Danger 的明确 Solid 外观。
- 真实进程 Shell 多色图标保留。没有改动 Hook/注入/采集协议或驱动操作。
- 已合并远端 `2c9645f3`（启动页面和标志更新）；双语冲突定点保留双方新增词条。新构建基于合并后的同一源码。

## 缓存和调度边界

按钮配方缓存按完整 QColor 输入、语义、状态和主题代次判等，同步主题预览旁路；不缓存 HWND 或业务采样。按钮所有权快路要求完整实际下发 QSS 精确匹配，业务改写后退回原所有权检查。

图标颜色状态仍区分 hover/focus/down/checked/disabled，源模式与 DPR 不固定。标题/导航明确 Flat 的语义保留，不把所有图标工具强制铺底。

旧色队列约 6ms、SVG 增量队列约 8ms 是控件之间让出的目标，不能中断单次 Qt setter/polish。全应用指针和局部基线快照仍同步读取。完成统计由最新任务回调报告，排队计数不当作已经完成。

完整且唯一的 TablePresentation 标记块更新不等于业务接管。旧色队列比较未变的业务片段并保留当前共享块；表格 Base/AlternateBase 由共享组件负责，其余显式画刷逐角色保留基线和连续链。标记缺失、不完整或重复时保留整串保护。
