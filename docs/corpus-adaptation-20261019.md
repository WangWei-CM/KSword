## 实体机 26H2 build 26300：Winbindex **无索引**

26H2 实体机的 R0 日志 (`.claude/memory/ksword-rxpf-mode1-realhardware-26h2-confirmed.md`) 对应 OS Build 26300.x，但 Winbindex 目前**没有收录任何** build 26300 的 ntoskrnl.exe（Flighting 期的 Insider 还没进 Winbindex 的发布追踪）。

现实选项：
1. **PDB ID 入口**：如果操作者从实体机导出了 ntoskrnl.exe 的 CodeView RSDS GUID+Age，可以直接用 NT Kernel Viewer 的 "PDB ID" tab 查询（Microsoft 公共符号服务器仍能按 GUID+Age 返 PDB，即使 Winbindex 没收录该 PE）。
2. **本地文件入口**：把实体机的 `C:\Windows\System32\ntoskrnl.exe` 走 NT Kernel Viewer 的 "本地文件" tab 让它本地解析。
3. 等 Winbindex 收录 26300 后重跑本流程。

无论哪种，**都不需要虚拟机**。

## 操作者下一步命令

### 1. 把 Winbindex 新发现的 build 28000 UBR 合进 corpus

**本次已在 `ksword_pdb_profile_generator.py` 加 `--kphdyn-extra` 支持**（可重复，按出现顺序合并，相同 `(file, version, arch)` 键后出现的覆盖前者）。不再需要手动拼 xml。upstream `third_party/systeminformer_dyn/kphdyn.xml` 保持不动（它标注 AUTOGENERATED）。

```powershell
py -3.12 tools\pdb_offset_generator\ksword_pdb_profile_generator.py `
    --kphdyn-extra tools\pdb_offset_generator\kphdyn-additions-ksword-20261019.xml `
    --version 10.0.28000 `
    --file ntoskrnl.exe `
    --symbol-root <private-corpus-root>
```

Merge 工作验证（smoke test 已通过）：

```
third_party/systeminformer_dyn/kphdyn.xml: +26 unique build-28000 UBRs
tools/pdb_offset_generator/kphdyn-additions-ksword-20261019.xml: +10 unique
Total merged: 36 unique (10.0.28000.1 .. 10.0.28000.3231)
```

Generator 本身要 llvm-pdbutil（默认在 `D:\Software\VS\VC\Tools\Llvm\x64\bin\llvm-pdbutil.exe`）+ `--symbol-root`（corpus 根，默认 `D:\PDB`）。本次工作宿主上这两样都不存在，所以 generator 的运行留给对应 corpus-root 节点上的操作者。

### 4. 实体机 26H2 (build 26300) 单独处理

见上节"实体机 26H2 build 26300：Winbindex 无索引"。等 Winbindex 收录仍不可行时，用本次新加的 helper 从实体机本地的 `ntoskrnl.exe` 直接生成 kphdyn 行：

```powershell
# 在实体机本机运行（或先把 ntoskrnl.exe 拷到 corpus 节点再跑）
python tools\pdb_offset_generator\kphdyn_entry_from_local_pe.py `
    C:\Windows\System32\ntoskrnl.exe `
    --show-codeview `
    --append tools\pdb_offset_generator\kphdyn-additions-ksword-realhw.xml
```

该脚本会：
- 用 SHA-256 + `pefile` 直接读 PE 头，拿到 TimeDateStamp / SizeOfImage / Machine / FileVersion
- 解析 CodeView RSDS，打印 PDB GUID+Age 和 Microsoft public symbol server 的 PDB 下载 URL（供 generator 下载 PDB）
- `--append` 时把 `<data>` 行插在目标 extensions xml 的 `</dyn>` 之前，重复可用

拿到 extensions xml 后，照本节 1 的用法再加一条 `--kphdyn-extra` 跑 generator。这条路径同样适用于 CI.dll（generator 的 `module_class_for_file` 已经把 CI.dll/CI.sys 映射到 class `ci`），只是现有的 pack v4 字段字典暂未包含 CI 结构偏移。

**26H2 实体机的 primary evidence 已记录在 memory**：[`ksword-rxpf-mode1-realhardware-26h2-confirmed.md`](../.claude/memory/ksword-rxpf-mode1-realhardware-26h2-confirmed.md)。只要操作者在实体机上跑这一条，就能把 R0 日志里 `MmChangeImageProtection VA = 0xfffff80498662300` 对应那份 ntoskrnl.exe 收编进 corpus，报告 §2 的 `<TBD-OPS: UBR>` 等占位符也可以同时在实体机上补齐（`HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\UBR` 读 UBR；`certutil -hashfile C:\Windows\System32\CI.dll SHA256` 读 CI.dll SHA-256）。
