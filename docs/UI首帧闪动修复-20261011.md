# 页面首帧闪动的时序修复

## 源码中确认的原因

- ThemeBinding 首次应用也进入分片队列。页面可先收到 Paint，再消费属于自己的主题请求；隐藏页重新显示时也可能仍有旧颜色。
- TablePresentation 在 Show 后排队修改 frame、grid、表头样式；PageTabEnvelope 和角片控制器也延迟准备外部留白与遮片几何，导致第一帧后的尺寸或边角变化。
- 详情侧栏首显定宽排队，恢复窗口大小后仍可能先绘制旧宽度。
- 按钮图标的身份变化在 Paint 中发现后仍只排队包装，第一帧可能使用原始图标；首次没有图标的按钮需要保留稍后第一个图标的准备机会。
- 内核页的初始化进度反馈调用全应用 processEvents，可能让构造未结束的页面和主题任务提前绘制。
- Dock 延迟可见回调未复核当前可见性，快速切页后仍可能初始化已经隐藏的旧页。

## 共享准备入口

新增 PrepareWidgetThemeBindingsForShow，仅在完整页面已构造、最终父级已建立后消费当前显示分支的既有绑定。MainWindow 真实内容挂载和 GlobalDialogTheme 根主题完成后的 Show 共用此入口；QStackedWidget 只收当前页，独立子窗口、隐藏页、Popup 和 Tooltip 不参与。

惰性子页由 ScopedWidgetThemePreparation 在统一工厂退出时调用相同入口，覆盖内核二/三级页、杂项全部子页、硬件磁盘/其他设备、监控直接内核调用/内核回调/WinAPI、内存工作台/内存调试和进程详情子页。守卫构造只记录弱引用，退出时只准备仍然可见的分支，避免在业务构造尚未完成或后台预建时调用主题。进程详情的四类内嵌 Dock 也在延迟构造阶段退出时共用该守卫：业务范围、内部页选择和显隐全部完成后才准备最终显示分支，保持原共享挂载 helper 和原有显隐流程。

首显与普通分片共用同一 dirty 请求。同步消费后旧 FIFO 节点不再重复执行；真正的新主题、重登记与嵌套刷新继续排队。首次动态叶控件在 Paint 前补本地颜色，已应用过的隐藏控件在重新 Show 时消费待刷新主题。初次构造的 Polish/Show 不直接调用未知业务绑定。

表格在自身 Show 统一呈现；页框在有效 Show/currentChanged 的安全点准备布局。Paint 只补既有覆盖层几何，不改变布局、pane 样式、模型或页面结构。已有角片先确定几何再显示，侧栏首显同步定宽；被消费的旧几何回调按代次失效。

SVG 首次颜色与首次实际图标准备分开，无图标 Paint 不提前消耗图标标记。内核等待反馈只同步 repaint 进度和说明，不派发全应用事件。Dock 延迟可见回调重新确认可见性。

## 保持的边界

- 保留原有外层 14px、内部 8px、等宽 6px 留白和无描边设计，未新增外框。
- 保留可见窗口连续缩放与正常换肤的分片合并，不预加载全部业务页或隐藏 Popup。
- 不使用全树禁绘、截图代理或伪窗口，避免浮动窗口继承禁绘后持续黑屏。
- 回调可能换页或销毁控件，首显和几何同步使用弱引用并复核当前页面身份。
- 用户已要求自行测试，本轮不运行自动测试或 GUI 验收；源码收齐后统一编译原 Release。编译结果不等于已确认消除全部实机闪动或测得耗时提升。
