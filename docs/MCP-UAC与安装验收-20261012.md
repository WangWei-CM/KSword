# MCP UAC 启动与安装验收修正

用户实测发现普通 agent 会被 `admin_client_required` 拒绝。本次管理员自动启动改为 Windows `runas`：用户确认 UAC 后启动 GUI，agent 本身保持原权限。

## 授权边界

- 默认连接仍要求本机、同用户 SID、同会话及同完整性级别。
- 普通 sidecar 启动 High GUI 时传入 `--mcp-uac-client PID:creationTime`。GUI 仅为这个活进程开放 Medium → High 例外，完整请求到达时再次核验，PID 复用者不能继承。
- sidecar 同时核对 ShellExecuteEx 返回的 GUI PID + 创建时间、完整映像路径和用户/会话。Qt `UserAccessOption` 已支持同用户未提权进程连接管理员服务器，不新增网络端口、ACL 开关或提权代理。
- 用户取消 UAC 返回 `uac_cancelled`；不自动重试。已有 GUI 不因 auto 重启，sidecar 退出后的授权不移交新进程。旧构建缺少授权标志时在弹 UAC 前拒绝启动。
- `ksword_hello` 的公开描述明确 auto 可能启动 GUI并请求 UAC；它自身不执行驱动装卸。

## 安装与界面

- README 首个提示词代码块、`agent_install_prompt.txt` 和“设置 → MCP → 安装提示词”资源同步；沿用 SecondaryPageLayout、CodeEditorWidget、固定动作工具行，无新增布局例外。
- 完整指南要求识别真实客户端/版本/配置作用域，核验环境变量重定向后的实际绝对路径，并在注册前保留可恢复配置基线到验收完成。非目标配置须对比，不能猜原值或覆盖并发修改。
- 验收分别报告：原生注册、独立 stdio 工具发现、当前 agent 工具加载、GUI hello/pages/snapshot 的只读连接。独立 SDK 不能替代当前会话的加载证据；受阻时继续完成独立步骤。
- 用户同意使用兼容预发行版后才下载相应主程序；发行包同时附带 `tools/ksword_mcp` 脚本与指南，Python 依赖仍由独立环境安装。
