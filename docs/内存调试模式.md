# 不附加内存调试

主程序“内存 → 内存调试”建立独立进程内存会话，并提供三种明确分开的运行控制方式。它们不调用 Windows 调试附加接口，也不借用 x64dbg/Titan 的调试事件循环。

## 使用

1. 进入“内存调试”，在选择器中搜索进程名称或输入列表里的十进制 PID，点击“打开不附加内存会话”图标。
2. 选择模块可在其基址处反汇编；也可在工作台地址栏输入地址或模块表达式。十六进制、反汇编、文本和对比视图共用同一份会话内存数据。
3. 通过既有编辑和汇编功能修改字节。写入模式沿用工作台设置，可立即写入或暂存后应用；写入仍执行身份核验、写前比对和最终回读。
4. 在运行控制区选择后端；图标的悬停释义说明刷新、捕获、暂停、继续、单步和寄存器查看的实际作用。
5. 关闭或切换先通过原有内存暂存离开守卫；取消时保留暂停状态。允许离开后再释放本页持有的运行控制，释放期间冻结工作台输入。恢复失败时保留旧目标及恢复入口，不执行调试分离、不终止目标。

内存 R3 通道无需驱动，访问受目标权限限制；其他内存通道仍按工作台的可用性和确认策略启用。运行控制后端独立选择，不能从内存通道名称推断实际单步机制。

## R3 线程检查

- 刷新后选择一个线程，可以短暂停顿捕获寄存器，或显式保持该线程暂停。其它线程继续运行，不声称全进程一致停止。
- 使用 PID/进程创建时间与 TID/线程创建时间双重身份，并保留对象句柄。只支持原生 AMD64，拒绝控制器自身、WOW64 和不支持的架构。
- 只归还本会话增加的一次挂起计数。发现目标已经被其它调用方挂起时，立即归还本次计数并拒绝接管；不循环恢复到零。
- 快照只读 GPR、RIP、RSP、RFLAGS 和 DR0–DR3/DR6/DR7。临时捕获后恢复的寄存器明确是历史快照；只有本会话仍暂停的现场才会触发 RIP 导航。
- 没有异常消费者，不能单步、步过或设置调试断点。不会向普通目标设置 TF 或试投 INT3。

用户态析构只能尽力恢复；控制程序被强制终止时没有可靠的析构恢复保证。Windows 挂起计数没有调用者标签，不能对并发使用 SuspendThread/ResumeThread 的其它工具承诺计数隔离。

## 协作 VEH 单步

目标需要主动调用 `tools/cooperative_debug/CooperativeDebugRuntime.h` 的 `Start`、`Checkpoint`、`Stop`，并静态链接示例运行时库。KSword 不自动注入 DLL，也不修改任意目标的异常分发器。

1. 按组件 README 构建并启动 `CooperativeDebugDemo.exe`，然后在本页选择它。
2. 选择“协作 VEH 单步”，点击连接图标。组件未主动启动、身份不符或权限不足时明确失败。
3. 点击暂停，请求在目标下一个主动检查点停止；尚未到达检查点时不会显示成已暂停。
4. 当前真实停点可单步或继续。单步由目标内 VEH 消费本会话设置 TF 后的真实异常，并发布新的整数寄存器现场；执行请求必须消费匹配的 stopId。
5. 关闭控制连接、控制器退出或租约过期时组件释放自己持有的线程。其它线程和外部异常保持原有处理。

该模式是主动协作的单线程调试，不能称为任意进程无组件调试。当前提供逐指令单步与继续，没有实现 x64dbg 的全部断点、步过、步出、追踪与 XSTATE 编辑能力。

## 实验 HVM 单线程单步

独立协议为 `shared/driver/KswordArkHvmNoAttachIoctl.h`，设备访问统一经 `ArkDriverClient/ArkHvmNoAttachClient`。它与原有依赖 Windows #DB 调试事件的 HVM 断点后端分开。

- 必须刷新并选择具有可靠身份的线程，再显式确认启动；选择模式、选择进程和只读能力查询均不启动虚拟化。
- 设计限定 Intel VMX、EPT、MBEC、MTF 与独占的 HVM 生命周期。已有外部准备/常驻或不兼容策略时拒绝接管，不代替其它所有者执行 STOP/TEARDOWN。
- 三个预建 EPT 根承担正常执行、用户取指门禁、内核入口门禁；MTF 只属于本会话的当前 CPU。目标代码、TF、DR 不作为实现手段修改，也不向 guest 注入调试异常。
- 只控制选定的用户态线程，其它线程继续；全系统内核/用户态转换会产生额外 VM exit。中断、异常投递、线程或现场变化必须使步进进入 Interrupted 或产生新停点，不能用历史快照假报完成。
- 当前停止文档独立发布 sessionId/stopId。OPEN 回执不确定时先查询恢复身份再关闭；关闭失败保留恢复入口。全核资源释放在后台执行。

这是实验代码路径。源码审查、协议校验和成功编译均不证明 MBEC/MTF 在实际机器上正确工作；本次不自动加载新驱动、开启 HVM 或改变虚拟机。硬件运行验收必须另行记录，不能描述为已实机稳定。

## 会话边界

- 本页的目标、数据缓存、导航历史和暂存修改独立于原工作台；原 Dock 附加或分离不会改变本页目标。
- 选择器同时读取同一进程对象的名称和创建时间；选择时再次核验 PID 与创建时间。无法取得强身份、身份不符或已退出的候选会被拒绝。
- 模块查询在后台运行，结果必须通过当前会话的目录所有者核验。迟到结果不会进入另一份会话。
- 检测到退出后，当前缓存标记为过期并禁止编辑、提交及新读请求。清会话推进代次，取消旧请求；再次使用必须选择有效的进程实例。
- 此页首次显示才创建工作台和枚举进程。后台任务只操作值、共享后端及回投门禁，页面销毁后不能访问控件；自有暂停及控制连接仍须清理。

## UI 接入

导航入口为“内存 → 内存调试”。页面属于专业反汇编/内存工作台，保留 `MemoryWorkbenchView` 内部模型、滚动和编辑器身份；外围目标/运行控制使用 `PrimaryPageStyle` 与 `NormalizeToolbarRow`。本次对照内存工作台和线程调用栈工具窗，未把通用参数框架嵌入专业视口。

寄存器窗口属于字段详情，使用 `StructuredFieldView` 的同一份不可变文档、`CreateDetailFieldProjection` 与 `DetailDialogChrome`；搜索、复制和导出共用该文档。窗口保持捕获时身份，不将后续运行伪装成仍在当前停点。
