# Issue 223：复杂报告二级子页

## 目标和截图核对

[Issue 223](https://github.com/KSwordDEV/KSword/issues/223) 的正文及四张评论截图均已查看。最新截图从 PDB Deep Runtime Catalog 开始出现长标签挤压、值区过窄、行内容裁切；旧截图还有多行重叠。用户提供的报告页规范要求固定工具行、分区摘要、子组折叠和字段行内展开。

原生产文档已经保留 `Domain → Type → Field → 属性` 和类型默认折叠状态，问题来自共享 `flattenFields()` 把所有层级摊成两列表单，并为全部叶字段创建两个 QLabel。一次报告追加九个目录，可能生成数千乃至数万个常驻字段控件。

## 导航和共享结构

| 真实入口/影响类型 | 分类 | 共享接入与边界 |
| --- | --- | --- |
| 进程 → 进程详细信息 → Process Detail Evidence → 概览 | 生命周期与字段诊断 | 保留已有状态、字段来源和独立正文滚动；详情窗口摘要与侧栏不变 |
| 同上 → 字段监视 | 专业操作 | 保留 HVM 监视动作、依赖和提示；没有修改驱动动作或权限语义 |
| 同上 → 结构报告 | 复杂字段报告 | 显式 `ksword_complex_report_source`，经 `DetailFieldProjection` 接入 `ComplexReportView` |
| 普通 PEB、内存证据和其它平面详情 | 普通字段详情 | 继续原卡片，不按字段数或长字符串自动升级为复杂报告 |

对照了 PDB 目录的真实嵌套节点、PE 解析文档及平面进程内存证据。可复用组件提供复杂正文，业务页面只登记用途；没有将参考图的“分区 1/字段 3”等占位名变成产品数据。

## 实现与语义

- `ComplexReportModel` 持有规范 `FieldDocument` 快照，以稳定整数索引和规范路径保留层级。数值/状态变化使用 `dataChanged`，真正的节点拓扑变化才重置；展开、选中与滚动恢复使用稳定路径。
- `ComplexReportDelegate` 仅绘制可见行，不创建每字段 QWidget，也不使用 `setIndexWidget()`。分区卡片底板贯穿缩进与正文区域，仅首末外沿圆角，分区之间留 8px；类型子组用轻量工具带，深层字段保持正文权重。复制动作只留在分区、类型与全文详情，普通字段用上下文菜单或 Ctrl+C。
- 字段组直接显示规范属性生成的 Offset/Type 摘要；展开字段后，真实属性连接成一张带路径标题和复制入口的内嵌圆角面。长字段或说明提供同一行下的全文展开，81 字符及多行值可展开；派生预览不写回规范文档，普通短属性不显示无意义箭头。Identity 与 Sample 独立成分区，采样字段和映射记录分别属于单一 Sample/Mappings 分区，不产生空标题。
- `ComplexReportView` 固定摘要和工具动作，树是报告唯一正文滚动者。摘要过长进入“更多分区”，不以横向滚动掩盖窄窗溢出。树操作条明确为 None，因为搜索、复制全部和完整导出已经在原工具行。
- 搜索包括折叠后代和完整原始值，父分区命中保留其子项。清空搜索恢复展开、选中和阅读位置；同结构新值产生的搜索命中也会展开祖先。没有匹配和没有报告分别显示明确空态。
- 分区/字段复制取完整规范子树；复制全部和导出继续复用原 `StructuredFieldView` 的完整快照，不按当前折叠或过滤截断。目录生产者原有的类型/字段截断说明仍保留，未载入的目录项不算作已展示或已导出。
- 状态是生产者明确的元数据。IO、采样协议、identity 和 Section 查询分别提供自己的真实状态；静态 PDB 目录保持中性，不因“刷新完成”显示采样成功绿点。未知状态也保持中性。
- 字号、颜色和圆角来自现有主题及详情组件。文字按实际正常/悬停/选中/禁用底色校准；纯主题刷新不重建报告模型或重新查询业务。
- 规范文档序列化拆到 `FieldDocument.cpp`，仍使用原递归实现。主工程及受影响的独立测试编译清单同步登记；语言包仅定点新增显示词。普通值更新不遍历旧树保存展开状态；真正重置时才保存，连续缩放合并重测。
